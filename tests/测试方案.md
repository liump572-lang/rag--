## 二、测试目标（对应 `测试.txt` 四大问题）

### 问题 1：复杂查询理解能力

> 当查询概念 A 与概念 D 之间的关联时，需要捕捉中间概念 B 和 C。

**测试场景**：
- 查询"梯度下降如何影响 Transformer 的训练？"
  - 期望路径：梯度下降 → 反向传播 → 神经网络训练 → Transformer 训练
  - 涉及文档：《梯度下降》《神经网络与深度学习》《Transformer7模型训练与评估》
- 查询"PyTorch 中如何实现神经网络的权重更新？"
  - 期望跨《李沐Dive-into-DL-Pytorch》《神经网络与深度学习》检索

### 问题 2：分布式来源整合

> 知识点分散在多份文档中，需建立跨文档的关联。

**测试场景**：
- "反向传播"概念出现在《李沐Dive-into-DL-Pytorch》《神经网络与深度学习》
- "注意力机制"涉及 Transformer 和深度学习两份文档
- 知识图谱应合并同义节点、建立跨文档关系边

### 问题 3：LLM 上下文窗口约束

> 超长文档需切片但保持语义完整性。

**测试场景**：
- 《李沐Dive-into-DL-Pytorch》（35 MB）的分块与索引
- 跨切片的对话上下文保持
- 切片边界处关键信息的保留

### 问题 4：系统效率与扩展性

> 多文档、大规模知识库的检索效率。

**测试场景**：
- 5 份文档全部上传 + 解析 + 向量化的耗时
- 并发问答请求的响应时间
- 知识图谱重建的完整流程

## 四、测试执行步骤

### 4.1 前置条件

```bash

pip install -r requirements.txt

# 启动必要服务（Docker）
docker-compose up -d mysql redis neo4j chromadb

# 初始化数据库
.venv\Scripts\python.exe -c "from app.main import app; print('OK')"

# 导入种子数据
.venv\Scripts\python.exe -m app.seed
.venv\Scripts\python.exe -m app.seed_kg
```

### 4.2 数据准备

```bash
# 上传 5 份测试文档到知识库
# 通过 API 或管理后台上传 资料/ 下的 PDF 文件
```

### 4.3 执行顺序

```
阶段 1: 文档解析 → 验证 PARSER-01 ~ PARSER-07
阶段 2: 文本分块 → 验证 CHUNK-01 ~ CHUNK-05
阶段 3: 向量索引 → 验证 VEC-01 ~ VEC-06
阶段 4: 知识图谱 → 验证 KG-01 ~ KG-10
阶段 5: 智能问答 → 验证 QA-01 ~ QA-10
阶段 6: 错题本   → 验证 WQ-01 ~ WQ-07
阶段 7: 学习心得 → 验证 NOTES-01 ~ NOTES-08
阶段 8: 系统管理 → 验证 ADMIN-01 ~ ADMIN-06
阶段 9: 安全认证 → 验证 AUTH-01 ~ AUTH-08
阶段 10: 通知   → 验证 NOTIF-01 ~ NOTIF-05
```

### 4.4 运行自动化测试

